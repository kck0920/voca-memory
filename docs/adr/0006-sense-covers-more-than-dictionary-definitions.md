# Sense는 사전 뜻에 한정하지 않는다

Sense는 사전의 뜻만이 아니라 다음 모두를 포함한다: 사전 뜻, 관용구(phrasal verb), 특정 문맥에서의 쓰임, **학습자가 직접 지은 뜻**. `senses` 테이블에 `kind`와 `source` 두 축을 두어 표현한다.

```
kind:   word | phrase | example
source: dictionary | user
```

## 왜 이 모양인지

- **문맥 예문도 Sense다.** "이 문장에서 `abandon`은 '포기하다'가 아니라 '떠나다'다"를 학습하고 싶다면, 예문 자체가 Sense가 되어야 복습 단위가 생긴다. 예문을 Card의 부가 정보로 두면 이 학습을 표현할 방법이 없다.
- **관용구는 이미 어휘다.** `run off`(도망치다)는 Wiktionary에도 사전 항목이 있지만, 모든 파생구문이 그렇지는 않다. `kind = phrase`로 분리해 둬야 사전 커버리지 부족을 사용자가 메울 수 있다.
- **사용자 정의가 필요하다.** 개인 어원, 특정 교재에서만 나오는 구어 표현, 이 앱 전용으로 지은 문장. 사전 단어만 허용하면 "내 단어를 못 넣는다"는 곧바로 보이는 벽이 된다.

## 다시 고른 대안: `cards.sentence_id`를 nullable로

Card가 Sense 또는 문장 중 하나를 가리키게 하면 Card 쪽 foreign key가 둘이 된다. 그 결과 스케줄링·통계·Mastery 계산의 모든 코드가 분기를 타게 된다. **복습 대상의 종류가 두 개가 된다는 것은 복습 대상의 정의를 두 개로 만든다는 뜻**이고, 그건 피하는 게 낫다. Sense를 확장하는 쪽이 훨씬 싸다.

## 대안의 함정

사용자 정의 Sense를 허용하면 화면에 저품질 항목이 쌓인다. "맛있다", "good" 같은 의미 없는 뜻도 들어온다. 이것은 다만 **검증에 필요한 문제가 아니라 화면에 보여줄 문제**로 치환한다 — Deck이 학습 단위이므로, 쓰레기가 한 덱에 몰려 있으면 그 덱을 버리면 된다. 그것도 싫으면 Sense에 `archived_at`을 둔다.

## 결과

- `senses.word_id`는 NOT NULL이다. 모든 Sense는 어떤 Word에 속한다.
- `source = user`인 Sense는 `words.lemma`를 자유 입력으로 허용한다. 사전 조회 결과와 섞이지 않도록 출처 배지가 필요하다.
- Sense를 자유롭게 만들 수 있다는 것은 **Word도 사용자 소유가 될 수 있다**는 뜻이다. 전역 사전(`source = dictionary`)과 사용자 단어를 같은 테이블에 두되, 전역 행은 쓰기 권한이 없다.
