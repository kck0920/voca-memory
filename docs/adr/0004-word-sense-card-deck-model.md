# Word : Sense : Card : Deck 도메인 모델

복습 단위를 4개 개념으로 쪼갠다. 용어 정의는 [`CONTEXT.md`](../../CONTEXT.md)에 있고, 여기서는 **왜 이 모양인지**를 남긴다.

```
Word 1 ─── N Sense 1 ─── 1 Card N ─── 1 Deck
```

## 왜 Word와 Card를 분리했는가

`run`은 명사(달리기), 동사(달리다), 관용구(run off, 도망치다)를 가진다. 이 셋을 한 덩어리로 학습하면 어느 뜻이 취약한지 알 수 없다. Sense를 경계로 삼아야 "run은 동사만 쉽고 관용구는 매번 다시 본다"는 신호가 나간다.

반대로 `Word 1 = Card 1`로 단순화하면 데이터는 쉬워지지만 다의어 학습이라는 이 어휘 앱의 핵심 가치를 잃는다. Sense를 넣는 것이 이 선택의 근거다.

## 왜 Card가 Deck에 하나만 속하는가

다대다로 만들면 "여러 덱에 들어가 있는 단어를 한 번만 학습하면 모든 덱의 진도가 함께 오른다"는 동작이 생긴다. 겉보기에는 편하지만, 진도가 어느 덱의 책임인지 모호해진다 — "수능은 끝났는데 TOEFL은 왜 안 올라가지" 같은 혼란이 그대로다. Anki도 단일 소속을 택하고, 복제를 통로로 다중 덱 참여를 지원한다. 검증된 선택이므로 같은 쪽을 택했다.

## 결과

- `Card`는 `sense_id`를 필수로 갖는다. 사용자 정의 문장 카드처럼 Sense가 없는 Card는 현재 모델에 들어갈 자리가 없다 — [`docs/design.md`](../design.md)의 미해결 질문 참조.
- `Card`를 복제하면 Memory State는 복제되지 않는다. 새 Card는 `New` 상태로 시작한다.
- 데크별 진도 집계는 자연히 성립한다. Card가 하나인 덱이므로 `count(*) by deck_id`가 곧 진도다.
