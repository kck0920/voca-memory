# UI를 첫날부터 CSR 호환으로 작성한다

모든 Leptos 컴포넌트는 클라이언트 사이드에서만 실행되어도 완전히 동작해야 한다. 서버 렌더링에 의존하는 코드는 금지한다.

## 이유

Tauri는 로컬 HTTP 서버를 호스팅할 수 없다. 공식 Tauri 문서의 Leptos 가이드는 이 때문에 SSG를 권장한다. 즉 나중에 데스크톱·모바일 앱을 만들면 그 앱은 **순수 CSR**로 동작한다.

- 웹: SSR로 hydrate
- Tauri: `mount_to_body`로 CSR

같은 컴포넌트 트리가 두 경로를 모두 견뎌야 한다. 이 제약이 없다면, 나중에 데스크톱을 붙이는 시점에 UI 전체를 다시 쓰게 된다.

## 구체적으로 금지하는 것

- `create_resource` / `create_local_resource` 중 서버 컨텍스트를 전제로 한 사용
- 서버에서만 존재하는 데이터로 컴포넌트가 첫 프레임을 결정하는 구조
- SSR 전용 메타데이터 렌더링에 의존하는 라우팅

`#[server]` 함수를 쓸 때는 `client = "..."`로 명시적 클라이언트 경로를 지정해, Tauri 빌드에서 원격 서버 주소로 나가는 동작이 되게 한다. 이 방식은 서버 함수를 나중에 네이티브 구현으로 교체할 여지를 남긴다.

## 대안의 함정

"웹에서는 SSR로 쾌감을 얻고, Tauri는 나중에 그 부분을 버리자." 이렇게 하면 Phase 3의 UI 작업이 통째로 폐기 대상이 된다. 어휘 앱은 SEO가 중요하지 않으므로 SSR로 얻는 이득도 크지 않다. 처음부터 양쪽 다 가능한 형태로 쓰는 편이 싸다.
