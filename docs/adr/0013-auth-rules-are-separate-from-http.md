# 인증은 규칙과 어댑터로 나눈다

인증 **규칙**(`voca-server/src/auth.rs`)은 프레임워크를 모른다. axum 핸들러도 Leptos 서버 함수도 아닌 순수 함수다. HTTP 는 그 위에 얇은 어댑터로 얹힌다.

## 왜

규칙을 웹 서버에 묶으면 두 가지를 잃는다. 하나는 **프레임워크 없이 시험할 수 없게 된다** — HTTP 왕복을 통째로 세워야 하므로 "미가입일 때 해시 검증을 생략하면 안 된다" 같은 규칙을 1줄 테스트로 못 확인한다. 다른 하나는 규칙이 **프레임워크의 생애에 묶인다** — Leptos로 갈아탈 때 인증을 통째로 다시 쓴다.

그래서 테스트는 `AuthContext` 에 저장소를 넣고 async 함수를 부른다. 서버를 띄우지 않는다.

## `AuthContext` 는 제네릭이지 `dyn` 이 아니다

`async fn` 이 든 트레잇은 `dyn` 호환이 되지 않는다. [ADR-0012](./0012-store-seam-is-domain-operations-not-table-crud.md)에서 같은 이유로 RPITIT 을 썼던 것과 같은 제약이다.

`Box<dyn Future>` 를 넣는 `#[async_trait]` 는 매 호출마다 할당이 생기므로 쓰지 않는다. 대신 하나를 나열한다 — `Accounts + Sessions` 를 모두 만족하는 타입이면 무엇이든 들어온다. 어댑터가 갈라지면 세 개를 함께 갈라야 하는데, 그게 어차피 같이 바뀌어야 하는 것들이기도 하다.

## 계정 존재 여부를 세 방법으로 가린다

이 모듈이 지킨 규칙 중 가장 중요한 것:

1. **메시지와 상태 코드가 같다.** 미가입과 비밀번호 오류는 401 + 같은 문구다.
2. **응답 시간도 비슷해야 한다.** 미가입이면 실제 검증이 없다. 그대로 두면 argon2id 19MB 검증을 하는 경로와 수십 ms 차이가 나고, 그 차이만으로 "이 이메일은 가입돼 있다"가 드러난다. 그래서 미가입 경로에서도 **더미 해시 검증을 돌린다** (`password::burn_time`).
3. **서버가 죽은 것은 503 으로 따로 올린다.** 사용자가 제대로 입력했는데 "비밀번호가 맞지 않습니다"를 받으면 아무것도 할 수 없다.

`AuthFailure::ServerDown` 은 재시도 가능하다는 뜻이라 `is_retryable()` 로 갈린다.

## 비밀번호는 글자 수로 재고, 길이 상한은 바이트로 잰다

비대칭이지만 의도적이다. 최소 길이를 바이트로 세면 한국어 8바이트가 2.6글자라 한국어 사용자의 실질 최소 길이가 3글자가 된다. 반대로 상한은 **바이트**가 맞다 — argon2 비용이 처리하는 바이트에 비례하므로, 거기에 상한이 DoS 방어선이다.

## 세션 토큰은 해시해서 저장한다

평문으로 두면 DB 를 유출한 사람이 곧바로 세션 탈취한다. "DB 만 새면 세션이 전부 살아 있다"는 단순 경로 하나를 없애는 것이 목적이다. 해시 조회가 오프라인 공격에 막히진 않지만 — 알고리즘이 공개돼 있으므로 — 그럼에도 하는 이유가 이것이다.

토큰 타입은 `Debug` 를 손으로 써서 값을 가린다. `SessionToken(<redacted>)` — 로그에 새면 끝이므로 컴파일러가 막아주는 편이 낫다.
